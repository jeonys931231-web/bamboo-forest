# 피부관리사 대나무숲

마스크팩 붙인 피부관리사 캐릭터로 대나무숲을 함께 걸으며 익명으로 이야기하는 웹 공간이에요.

- 주소(배포 후): https://jeonys931231-web.github.io/bamboo-forest/
- 화면: GitHub Pages (무료)
- 실시간 연결: Firebase Realtime Database + 익명 로그인 (무료 Spark 요금제로 시작)

## 들어 있는 파일

| 파일 | 하는 일 |
| --- | --- |
| `index.html` | 숲 화면 전체 |
| `config.js` | Firebase 연결 정보를 붙여 넣는 곳 |
| `database.rules.json` | Firebase 보안 규칙. 콘솔에 붙여 넣어요 |
| `og.jpg` | 카톡·인스타에 링크를 보낼 때 뜨는 미리보기 이미지 |
| `icon.png` | 폰 홈 화면에 추가할 때 쓰는 아이콘 |
| `about.html` | 검색엔진과 AI가 읽는 소개·자주 묻는 질문 페이지 |
| `sitemap.xml` | 검색엔진에 제출하는 페이지 목록 |
| `llms.txt` | ChatGPT·Perplexity 같은 AI 검색이 읽기 좋게 정리한 소개 |
| `robots.txt` | 검색 허용 설정. 도메인 맨 앞(루트)에 있을 때만 적용돼요 |
| `_config.yml` | README·보안 규칙·원본 소스가 사이트에 공개되지 않게 막는 설정 |
| `_src/` | 원본 소스와 빌드 도구. 사이트에는 올라가지 않아요 |

## 배포 순서

### 1. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 에서 **프로젝트 추가**를 눌러요. 이름은 `bamboo-forest`처럼 아무거나 써도 돼요.
2. Google 애널리틱스는 꺼도 돼요.
3. 요금제는 기본값인 **Spark(무료)** 그대로 둬요.

### 2. Realtime Database 만들기

1. 왼쪽 메뉴 **데이터베이스 및 스토리지 → Realtime Database → 데이터베이스 만들기**를 눌러요. 메뉴가 안 보이면 맨 위 **제품 검색**에 `Realtime`을 입력해도 돼요.
2. 위치는 **싱가포르(asia-southeast1)**를 골라요. 한국에서 가장 가까워요.
3. 보안 규칙은 **잠금 모드로 시작**을 골라요.
4. 만들어지면 **규칙** 탭에서 기존 내용을 모두 지우고, `database.rules.json` 내용을 통째로 붙여 넣은 뒤 **게시**를 눌러요.

### 3. 익명 로그인 켜기

1. 왼쪽 메뉴 **보안 → Authentication → 시작하기**를 눌러요. 제품 검색에 `Authentication`을 입력해도 돼요.
2. **로그인 방법 → 익명**을 켜고 저장해요.
3. **설정 → 승인된 도메인 → 도메인 추가**에 `jeonys931231-web.github.io`를 넣어요.

### 4. 웹 앱 등록하고 config.js 채우기

1. **프로젝트 개요** 화면의 **+ 앱 추가**를 누르고 웹 아이콘(`</>`)을 골라요. 나중에 다시 볼 때는 왼쪽 **설정 → 프로젝트 설정 → 일반 → 내 앱**에 있어요.
2. 앱 닉네임을 아무거나 쓰고 **앱 등록**을 눌러요. Firebase 호스팅은 체크하지 않아요.
3. 화면에 나오는 `firebaseConfig`에서 `apiKey`, `authDomain`, `databaseURL`, `projectId`, `appId` 다섯 개를 `config.js`의 같은 이름 칸에 옮겨 적어요.
4. `databaseURL`이 안 보이면 Realtime Database 화면 맨 위의 주소(`https://…asia-southeast1.firebasedatabase.app`)를 복사해 넣어요.

이 값들은 원래 누구에게나 보이는 공개용 값이라 깃허브에 올려도 괜찮아요. 실제 보호는 2번에서 넣은 보안 규칙이 맡아요.

### 5. GitHub Pages에 올리기

1. github.com에서 **New repository**를 눌러 이름을 `bamboo-forest`로, 공개 범위를 **Public**으로 만들어요.
2. **uploading an existing file**을 눌러 파일 다섯 개(`index.html`, `config.js`, `database.rules.json`, `og.jpg`, `icon.png`)와 이 README를 끌어다 놓고 **Commit changes**를 눌러요.
3. **Settings → Pages**에서 Branch를 `main`, 폴더를 `/ (root)`로 고르고 **Save**를 눌러요.
4. 1~2분 뒤 https://jeonys931231-web.github.io/bamboo-forest/ 가 열려요.

### 6. 확인

폰과 PC로 같은 주소에 들어가서 왼쪽 위에 **숲 1 · 2명**이 보이면 성공이에요.

## 숲 나누기와 움직임 줄이기

사용량을 아끼려고 두 가지를 넣었어요.

- **숲 나누기**: 한 숲에 25명이 차면 다음 사람은 **숲 2**, 그다음은 **숲 3**으로 저절로 안내돼요(숲은 8개까지). 각자 자기 숲 사람들의 움직임만 받아서, 100명이 와도 사용량이 4분의 1쯤으로 줄어요. 왼쪽 위 숲 번호를 누르면 숲마다 몇 명인지 보이고, 친구가 있는 숲으로 옮길 수 있어요. 숲 크기는 `config.js`의 `cap`으로 바꿔요.
- **움직임 줄이기**: 화면을 눌러 걸을 때는 '어디로 간다'만 한 번 보내고, 걸어가는 모습은 각자 화면에서 그려요. 방향키는 누르는 방향이 바뀔 때만 보내요. 위치 확인은 1~1.5초에 한 번만 가요. 예전에는 걷는 동안 1초에 6~7번 보냈어요.

이 칸(`tx`, `ty`, `kx`, `ky`)은 보안 규칙에 들어 있어요. 예전 규칙이면 숲은 그대로 돌아가지만, 걷는 동안 위치를 자주 보내서 절약 효과가 없어요.

## 겨울 숲 (계절)

날짜에 따라 숲이 저절로 바뀌어요. 날짜는 한국 시간으로 세서 모두 같은 숲을 봐요.

- **11월~2월**: 눈이 내리고, 땅·지붕·벤치·등불에 눈이 쌓이고, 연못이 얼어요. 걸으면 발자국이 남고 눈 밟는 소리가 나요.
- **11월~12월**: 마당 오른쪽에 크리스마스 트리와 선물 상자, 마스크팩을 붙인 눈사람 둘, 토닥정 처마의 꼬마전구, 표지판 리스가 생겨요. 배경음에 오르골 캐롤(고요한 밤, 징글벨, 우리 모두 즐거운 성탄, 덱 더 홀)이 흘러요. 소리 조절 메뉴에서 캐롤만 끌 수 있어요.
- **의상**: 산타 옷, 루돌프 옷, 크리스마스 니트, 머리에 쓰는 산타 모자와 루돌프 뿔(빨간 코, 밤에 빛나요)은 언제든 고를 수 있어요. 처음 온 사람에게 무작위로 입혀 주는 건 11~12월에만 해요.

날짜와 상관없이 고정하려면 `config.js`의 `season`을 `"christmas"`, `"winter"`, `"off"` 중 하나로 바꿔요. 주소 뒤에 `?season=off`처럼 붙이면 그 화면에서만 미리 볼 수 있어요.

**보안 규칙을 한 번 더 게시해야 해요.** 새 의상 번호가 들어가도록 꾸미기 칸의 범위를 넓혔어요(나중에 옷을 더 넣어도 규칙을 안 바꿔도 되게 넉넉히). Firebase 콘솔 **Realtime Database → 규칙**에서 기존 내용을 지우고 새 `database.rules.json`을 붙여 넣은 뒤 **게시**를 눌러요. 게시 전에는 겨울 옷을 고른 사람이 다른 사람 화면에 기본 옷으로 보여요. 숲은 그대로 돌아가요.

## 숲속 마당과 꼬마 캐릭터

- **숲은 마당 하나예요.** 대나무로 둘러싸인 아담한 숲속 마당에 토닥정, 잉어 연못, 약수터, 벤치가 모여 있어요. 아래쪽은 낮은 꽃덤불이라 사람들이 가려지지 않아요. PC에서는 마당이 거의 한 화면에 들어오고, 폰에서는 내 캐릭터를 따라 화면이 움직여요.
- **캐릭터는 머리가 크고 손발이 짧은 꼬마 비율이에요.** 큰 눈, 볼터치, 고양이 입, 옆머리가 얼굴을 감싸요. 걸을 때 뒤뚱거리고, 기지개를 켜면 짧은 팔을 머리 옆까지 쭉 올려요. 의상·머리띠·모자는 예전 것 그대로 꼬마 몸에 맞게 그려져요.
- **예전 화면과는 따로 놀아요.** 지도가 바뀌어서, 새 화면은 Firebase의 다른 칸(`rooms/main-w2`)을 써요. 예전 화면을 켜 둔 사람은 새로고침하면 넘어와요. 이 변경 때문에 보안 규칙을 또 바꿀 필요는 없어요(겨울 옷 때문에 넓힌 규칙은 위 '겨울 숲'에 적은 대로 한 번 게시해야 해요).
- **느린 폰에서도 걷는 속도가 같아요.** 화면이 느리게 그려져도 걷는 거리는 실제 시간대로 계산해서, 다른 사람 화면과 어긋나지 않아요.

## 연결이 안 될 때 뜨는 안내

무료 사용량을 다 쓰거나 동시 접속 100명이 차서 서버에 연결이 안 되면, 15초쯤 뒤에 왼쪽 위가 **나홀로 대나무숲**으로 바뀌고 이 안내가 떠요.

> 접속량이 많아 현재 나홀로 대나무숲으로 실행중이에요! 얼른 서버를 확보해볼게요!

- 혼자 걷기, 꾸미기, 감정 표현, 배경음은 그대로 돼요.
- 입장 화면에서도 '지금은 접속량이 많아 나홀로 대나무숲으로 열려요.'가 보여요.
- 자리가 나거나 서버가 다시 열리면 새로고침 없이 저절로 숲에 이어지고, 안내가 사라져요.
- 인터넷 자체가 끊긴 경우에는 '인터넷 연결이 끊겼어요…' 안내가 대신 떠요.

## 무료로 쓸 수 있는 범위

| 항목 | 무료 한도 | 넘으면 |
| --- | --- | --- |
| 동시 접속 | 100명(모든 숲 합쳐서) | 101번째 사람부터 '나홀로 대나무숲'으로 열려요. 자리가 나면 저절로 이어져요 |
| 다운로드 | 월 10GB | 그달 남은 기간 동안 모두 '나홀로 대나무숲'으로 열려요 |
| 익명 로그인 | 하루 3천 명, 월 5만 명 | 새 방문자가 로그인을 못 해요 |
| GitHub Pages | 월 100GB 정도 | 사실상 걱정 없어요 |

카드를 등록하지 않았으면 한도를 넘어도 돈이 나가지 않아요. 연결만 막혀요.

다운로드는 같은 숲 사람들끼리 움직임과 말을 주고받으면서 쌓여요. 숲 나누기와 움직임 줄이기를 넣은 지금 기준으로, 이만큼 놀면 월 10GB에 가까워져요.

| 동시에 노는 사람 | 매일 이만큼 |
| --- | --- |
| 10명 | 15시간쯤(사실상 하루 종일) |
| 25명(숲 하나가 꽉 참) | 2~3시간 |
| 100명(숲 4개) | 40분쯤 |

걷는 시간이 전체의 4분의 1쯤이라고 잡은 어림값이에요. 실제 사용량은 콘솔 **Realtime Database → 사용량** 탭에서 봐요.

## 유료로 넘어갈 때

**넘어갈 신호**: Firebase 콘솔 **Realtime Database → 사용량** 탭에서 동시 연결 최고치가 80명 근처이거나, 그달 다운로드가 8GB를 넘으면 준비하면 돼요.

**방법**: 콘솔 왼쪽 아래 **업그레이드 → Blaze(종량제)**를 고르고 카드를 등록하면 끝이에요. 코드는 손댈 필요가 없어요.

**요금**

- Blaze에도 무료분이 그대로 들어 있고, 넘는 만큼만 내요.
- 다운로드는 1GB에 1달러, 저장은 1GB에 월 5달러예요. 저장은 거의 쓰지 않아요.
- Blaze에서는 다운로드 무료분이 하루 360MB씩 계산돼요.
- 동시 접속 한도는 20만 명으로 늘어나요.

**꼭 해둘 것**: Google Cloud 콘솔 **결제 → 예산 및 알림**에서 예산 알림(예: 5달러)을 걸어두세요. 알림만 오고 자동으로 멈추지는 않아요.

**주의**: Google Cloud에 결제 계정(카드)을 연결하면 Firebase가 Blaze로 자동으로 바뀔 수 있어요. 무료로만 쓰는 동안에는 결제 계정을 연결하지 마세요.

## 안 될 때

왼쪽 위에 **나홀로 대나무숲**이나 **혼자 걷는 중**이 뜨면 이것부터 확인하세요.

1. Firebase 콘솔 **Realtime Database → 사용량**에서 그달 다운로드가 10GB를 넘었거나 동시 연결이 100에 닿았는지
2. `config.js`의 다섯 칸이 비었거나 따옴표가 빠지지 않았는지
3. 익명 로그인을 켰는지
4. 보안 규칙을 붙여 넣고 **게시**까지 눌렀는지
5. `databaseURL`이 들어 있는지

PC 브라우저에서 F12 → Console을 열면 `forest:`로 시작하는 안내가 보여요. 깃허브에서 `config.js`를 고친 뒤 1~2분 지나 새로고침하면 반영돼요.

## 들어 있는 안전장치

- 다른 사람의 캐릭터 위치·이름·말을 바꾸거나 지울 수 없어요(보안 규칙).
- 너무 빠른 반복 쓰기(도배), 30자 넘는 이름, 200자 넘는 말은 서버가 거절해요.
- 심한 욕은 ♡로 바뀌어 보여요.
- 불편한 사람은 캐릭터를 눌러 **이 사람 말 숨기기**를 하면 돼요. 내 기기에만 적용돼요.
- 대화는 저장하지 않아요. 보낸 말은 10초 동안만 서버를 거쳐 가고 지워져요. 나중에 들어온 사람에게는 이전 대화가 보이지 않아요.
- 서버에 남는 건 익명 아이디, 숲에서 쓰는 이름, 캐릭터 모양과 위치뿐이에요. 이메일이나 전화번호는 받지 않아요.

## 검색 노출 (SEO·GEO)

숲 화면은 대부분 그림(캔버스)이라 검색엔진과 AI가 읽을 글이 거의 없어요. 그래서 이렇게 보강해 뒀어요.

- **소개 페이지(`about.html`)**: 대상, 할 수 있는 것, 대화 처리 방식, 자주 묻는 질문 7개를 글로 담았어요. "피부관리사 대나무숲", "피부관리사 메타버스"가 자연스럽게 들어가요.
- **입장 화면**: '대나무숲이 뭐예요?'를 펼치면 짧은 소개가 나오고 소개 페이지로 이어져요. 자바스크립트 없이도 읽혀요.
- **검색 정보**: 페이지마다 제목, 설명, 대표 주소(canonical), 공유 미리보기를 넣었어요. 구조화 데이터(웹사이트, 웹 앱, 자주 묻는 질문, 경로)도 넣어서 구글과 AI가 무엇인지 정확히 알 수 있어요.
- **AI 검색용(`llms.txt`)**: AI가 인용하기 좋게 핵심 사실만 정리했어요.

### 검색엔진에 등록하기

GitHub Pages가 켜져서 사이트가 열린 뒤에 해요.

1. **구글 서치 콘솔**
   - https://search.google.com/search-console 에서 **속성 추가 → URL 접두어**에 `https://jeonys931231-web.github.io/bamboo-forest/`를 넣어요.
   - 확인 방법은 **HTML 태그**를 골라요. `content="…"` 안의 값을 Claude에게 주면 넣어 드려요.
   - 확인이 되면 **Sitemaps**에 `sitemap.xml`을 제출해요.
2. **네이버 서치어드바이저**
   - https://searchadvisor.naver.com 의 **웹마스터 도구 → 사이트 등록**에 주소를 넣고, **HTML 태그** 인증 값을 Claude에게 줘요.
   - 인증이 되면 **요청 → 사이트맵 제출**에 `sitemap.xml`을, **웹 페이지 수집**에 메인과 `about.html` 주소를 넣어요.
   - 하위 경로 주소(…/bamboo-forest/)가 등록되지 않으면, 도메인이나 조직 주소로 옮긴 뒤 등록해요.
3. **빙 웹마스터 도구**: https://www.bing.com/webmasters 에서 **구글 서치 콘솔에서 가져오기**를 누르면 끝이에요. ChatGPT 검색 같은 AI 답변이 빙 색인을 함께 써요.
4. **바깥 언급**: 네이버 블로그·카페, 인스타에 소개 글과 링크를 올려 두면 검색과 AI 답변에 함께 잡히기 쉬워요.

### 알아둘 것

- `robots.txt`는 도메인 맨 앞에 있어야 읽혀요. 지금 주소에서는 효과가 없지만, 막아둔 게 없어서 검색에는 문제없어요.
- 요금제를 올려 동시 접속 한도가 바뀌거나 `cap`을 바꾸면 `_src/site_src`의 `faq.json`과 `llms.txt`에 있는 '25명', '100명' 문구도 고친 뒤 다시 만들어요.

## 고칠 때

`_src/`에 원본이 있어요. 주소를 바꾸거나 소개 글을 고친 뒤 다시 만들 때는 이렇게 해요.

```
python3 _src/build.py _src/bamboo-forest.html _src/site_src . https://새주소/
```

## 시험용 숲

`config.js`의 `room`을 `"test"`로 바꾸면 본 숲과 완전히 따로 노는 시험용 숲이 돼요.
